# M7 上下文管理实战示例

本示例使用 `docs/copilot-cli-journey/` 学习中心本身作为练习对象，目标是把 Copilot 当作“文档维护助手”来训练，而不是只拿它分析业务代码。

## 练习目标

通过这组练习，你应该能：

- 让 Copilot 快速找到关键文件并解释职责
- 判断 M7 相关修改范围，区分必须改、可选改、不要改
- 拆解 M7 文档开发任务，形成可执行的多文件计划
- 基于 diff 审查变更，识别不相关改动和结构问题

## 练习 1：建立上下文地图

**练习提示词：**

```text
你现在要把 docs/copilot-cli-journey/ 当作一个完整学习项目来分析。

请先只阅读这个目录下最关键的说明文件，不要修改任何代码或文档。
你的任务是建立“上下文地图”，输出：
1. 关键文件列表
2. 每个文件的职责
3. 文件之间的关系
4. 可能需要修改的位置

请重点识别以下文件：README.md、INDEX.md、STRUCTURE.md、template.md。
同时识别 modules/、docs/、examples/ 三层结构分别承担什么职责。

输出要求：中文、分点清晰、不要编造不存在的文件。
```

**成功标准：**

- 明确识别 `README.md`
- 明确识别 `INDEX.md`
- 明确识别 `STRUCTURE.md`
- 明确识别 `template.md`
- 能说清 `modules/`、`docs/`、`examples/` 三层结构的关系
- 不修改任何代码或文档

## 练习 2：收敛 M7 修改范围

**练习提示词：**

```text
你已经知道 docs/copilot-cli-journey/ 的整体结构。

现在请专注于 M7 上下文管理相关改动，帮我收敛修改范围。
请把所有可能受影响的内容分成三类：
1. 必须修改
2. 可能修改
3. 不应修改

请特别判断以下范围：主模块、docs/phase3、examples/phase3。
同时明确说明为什么 Phase 1 和已完成 Phase 2 示例代码不应被改动。

输出要求：中文、表格优先、给出理由。
```

**成功标准：**

- 把范围拆成“必须修改 / 可能修改 / 不应修改”
- 覆盖主模块
- 覆盖 `docs/phase3`
- 覆盖 `examples/phase3`
- 明确说明不应修改 Phase 1
- 明确说明不应修改已完成 Phase 2 示例代码

## 练习 3：拆解多文件任务

**练习提示词：**

```text
请把一个 M7 文档开发任务拆成 4 个步骤。

任务背景：需要补充 M7 的主模块、Prompt 库、实战示例和导航同步。

请输出：
1. 这 4 个步骤分别做什么
2. 每一步依赖什么输入
3. 每一步的输出是什么
4. 哪一步最容易出错

输出要求：中文、按步骤编号、不要省略依赖关系。
```

**成功标准：**

- 拆成 4 个步骤
- 覆盖主模块
- 覆盖 Prompt 库
- 覆盖实战示例
- 覆盖导航同步

## 练习 4：基于 diff 审查

**练习提示词：**

```text
请基于以下 diff 进行审查，重点关注上下文管理相关问题。

请检查：
1. 学习中心结构是否被误改
2. M7 Prompt 库是否与主模块一致
3. Phase 3 示例导航是否同步更新
4. 是否存在不相关改动

输出要求：中文，按“问题 / 影响 / 建议”格式输出。
```

**成功标准：**

- 能检查学习中心结构
- 能检查 M7 Prompt 库
- 能检查 Phase 3 示例导航
- 能识别不相关改动

## 本次实战结论

M7 的实战验证已经完成，产出包括：

1. **上下文地图**：确认学习中心的 4 个入口文件和 3 层资料结构。
2. **范围收敛**：确认 M7 只需要更新 Phase 3 相关资料，不修改 Phase 1/Phase 2 已完成内容。
3. **多文件计划**：形成“示例记录 → 完成总结 → 导航同步 → 验证检查”的收尾顺序。
4. **diff 审查**：以最小上下文检查 M7 状态、链接和范围边界。

完成这组练习后，M7 可以从“初稿完成、待实战验证”更新为“已完成并可复习”。
