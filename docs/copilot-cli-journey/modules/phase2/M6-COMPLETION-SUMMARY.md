## 💡 关键改进模式

### 从 M6 学到的 5 个最重要的改进模式

#### 模式 1: N+1 → 批量查询

**适用**: 任何循环数据库操作

```python
# ❌ 错误
for id in ids:
    db.query(id)  # N 次查询

# ✅ 正确
db.query_batch(ids)  # 1 次查询
```

**效果**: 100-10000 倍性能提升

#### 模式 2: 字符串拼接 → 参数化查询

**适用**: 所有数据库操作

```python
# ❌ 不安全
query = f"... WHERE id = {user_id}"

# ✅ 安全
query = "... WHERE id = ?"
execute(query, (user_id,))
```

**效果**: 100% 防止 SQL 注入

#### 模式 3: 弱加密 → 强加密

**适用**: 密码、敏感数据

```python
# ❌ 弱
hash = hashlib.md5(password)

# ✅ 强
hash = bcrypt.hashpw(password, salt)
```

**效果**: 防止暴力破解，安全性提升 ∞

#### 模式 4: 混乱 → 分层

**适用**: 复杂的业务逻辑

```
# ❌ 混乱
class UserService:
    # 数据库 + 业务 + 转换 混在一起

# ✅ 分层
Repository (数据) → Service (业务) → DTO (格式)
```

**效果**: 可测试性从 0% → 95%

#### 模式 5: 无文档 → 完整文档

**适用**: 所有代码

```python
# ❌ 无文档
def get_users(ids):
    ...

# ✅ 有文档
def get_users(ids: List[int]) -> List[Dict]:
    """获取用户信息
    
    Args:
        ids: 用户 ID 列表
    
    Returns:
        用户信息字典列表
    """
```

**效果**: 新手快速理解，维护成本大幅下降

### Q: 我已完成 M4-M5，现在应该做什么？

1. ✅ 立即: 在项目中应用 M6 Prompt 库
2. 📊 本周: 量化改进效果（类似 quality-report.md）
3. 🚀 下周: 集成到团队流程（GitHub Actions）

### Q: 代码审查和单元测试有什么区别？

**A**:
- **测试 (M4)**: 验证代码是否按预期工作 (功能正确性)
- **审查 (M6)**: 评估代码质量、安全性、可维护性 (代码质量)
- **两者互补**: 测试 catch bug，审查 prevent 坏设计

### Q: 如何说服团队采用这个审查方法？

**A**:
1. 选择 1-2 个项目试点
2. 应用 M6 Prompt 库，记录改进效果
3. 展示数据: 性能提升、bug 减少、维护成本下降
4. 制定团队规范，逐步推广
