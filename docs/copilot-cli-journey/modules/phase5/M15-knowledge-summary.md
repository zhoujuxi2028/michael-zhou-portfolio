# M15: 个人知识库总结与迭代

## 概览

你已经走过了从 M1 到 M14 的完整学习路径，现在是时候把零散的经验沉淀为**可持续演进的个人知识库**。本模块不是终点，而是一个**反思和启动下一轮迭代**的节点。通过整理 Prompt 库、总结 CLI vs IDE 的个人判断框架、制定持续优化计划，你将把这段学习经历转化为长期的竞争优势。

---

## 核心概念 (理论 ~ 30-40%)

### 概念 1: 知识沉淀的三种形式

| 形式 | 内容 | 复用场景 |
|------|------|---------|
| **Prompt 模板** | 经过验证的高效提示 | 日常工作中直接复用 |
| **经验笔记** | 成功和失败的案例总结 | 遇到类似场景时参考 |
| **工作流脚本** | 可直接运行的自动化脚本 | 团队共享和自我提速 |

### 概念 2: CLI vs IDE 插件的个人判断框架

经过 M1-M14 的学习，你应该能建立自己的判断标准：

| 场景 | 推荐工具 | 判断依据 |
|------|---------|---------|
| 实时代码补全 | IDE 插件 | 即时反馈，无需手动触发 |
| 分析整个文件 | CLI | 文件输入更方便 |
| 生成测试套件 | CLI | 可以批量处理，精确控制输出 |
| 快速解释片段 | 两者都可以 | 取决于你在哪个环境工作 |
| 跨文件任务 | Workspace | 自动管理文件依赖 |
| CI 自动化 | CLI | 可在脚本中嵌入 |

### 概念 3: 持续迭代的价值

Copilot CLI 本身在不断进化，你的使用方式也应该持续优化。有效的迭代周期：

```
每周：记录 2-3 个有效的新提示，归档失败案例
每月：整理 Prompt 库，合并相似模板，删除过时的
每季度：评估 CLI vs IDE 判断框架是否需要更新
半年：全面回顾学习路径，识别知识盲点
```

## 实战应用 (70% 以上)

### 场景 1: 整理个人 Prompt 精华库

**问题描述**

经过 M1-M14 的学习和实践，你积累了大量提示经验，但分散在各处。需要整理成一份随时可用的精华库。

**整理方法**

```bash
# Step 1：用 Copilot 帮你梳理现有的提示记录
cat << 'EOF' | gh copilot suggest
我整理了以下在过去 3 个月中使用 Copilot CLI 的提示记录（摘要）：

测试场景：
- 为 Python 函数生成 10 个 Pytest 测试（效果好）
- 直接说"生成测试"（效果差，太简短）
- 指定"3 happy path + 3 edge case + 3 error"（效果最好）

文档场景：
- "生成 Docstring"（效果差）
- "生成 Google 风格 Docstring，包含 Args/Returns/Raises/Examples"（效果好）

请帮我：
1. 提取这些提示的共同规律（什么让提示更有效）
2. 为每个场景生成一个"最佳模板"
3. 指出我目前可能遗漏的场景
EOF
```

**精华库结构建议**

```
personal-copilot-prompts/
├── README.md         # 库的使用说明和统计
├── 01-testing.md     # 测试相关提示
├── 02-documentation.md
├── 03-code-review.md
├── 04-debugging.md
├── 05-git-workflow.md
└── CHANGELOG.md      # 记录每次更新的理由
```

**每条模板的标准格式**

```markdown
### 场景名称：[场景描述]

**适用情况**：[什么时候用这个提示]

**提示模板**：
```
[实际提示内容，用 {占位符} 标注可变部分]
```

**效果评分**：⭐⭐⭐⭐⭐  
**最后验证日期**：2026-04-28  
**已知局限**：[这个提示在什么情况下效果不好]
```

### 场景 2: 编写个人学习总结

**问题描述**

完成 M1-M15 后，你需要写一篇总结，一方面巩固所学，另一方面可以分享给团队或作为 portfolio 展示。

**Copilot CLI 辅助生成总结框架**

```bash
cat << 'EOF' | gh copilot suggest
请帮我生成一个"GitHub Copilot CLI 学习总结"的写作框架，
面向：QA 工程师同行，有 1 年以上测试经验
内容：3 个月深度学习 Copilot CLI 的关键洞察

框架要包含：
1. 执行摘要（3-5 句话概括最重要的发现）
2. 最有效的 5 个使用场景（附效率数据）
3. 超出预期的发现（意想不到的好效果）
4. 局限性和不适用场景（保持客观）
5. 给其他 QA 工程师的 3 条建议

每个部分提供 3-5 个占位问题，帮我引导自己写完
EOF
```

**关键洞察记录模板**

```markdown
## 最重要的 5 个发现

### 1. [洞察标题]
**原来的工作方式**：[描述 Copilot 之前怎么做]
**用了 Copilot 之后**：[描述新方式]
**效率变化**：[定量描述，如"从 30 分钟降到 5 分钟"]
**关键要点**：[这个场景成功的核心原因]

### 2. ...
```

## CLI vs IDE 插件：M1 到 M15 的综合回顾

经历完整学习路径后，你应该能得出更细化的判断：

| 维度 | CLI 更适合 | IDE 插件更适合 |
|------|-----------|--------------|
| **工作场景** | 终端、CI、脚本 | 编辑器内实时开发 |
| **任务类型** | 分析、生成、批量处理 | 代码补全、重构建议 |
| **上下文来源** | 文件、Git Diff、日志 | 光标位置、当前文件 |
| **输出控制** | 高（精确格式要求） | 中（接受建议或拒绝） |
| **自动化能力** | 强（可嵌入脚本） | 弱（依赖 IDE）|

## 常见错误与调试

| 问题 | 症状 | 原因 | 解决方案 |
|------|------|------|---------|
| 知识沉淀停滞 | Prompt 库几个月没更新 | 日常太忙，没有固定时间 | 设置每周固定 30 分钟整理时间 |
| 总结流于形式 | 写了但没有实际参考价值 | 只记录"是什么"，没有"为什么" | 每条经验都要写清楚触发场景 |
| 计划过于宏大 | 3 个月计划但完成率不到 30% | 目标不够具体可执行 | 把月度目标拆成每周行动项 |
