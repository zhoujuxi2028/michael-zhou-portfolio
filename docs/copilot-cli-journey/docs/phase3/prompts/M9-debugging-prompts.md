# M9 调试与故障排查 Prompt 模板库

本模板库用于识别低质量 Copilot 建议、系统化迭代提示，以及处理幻觉输出。

## 快速选择表

| 场景 | 推荐模板 | 目标 |
|------|---------|------|
| 分析复杂错误根因 | T1 根因分析 | 区分根因与次生错误，给出修复方向 |
| 诊断低质量建议 | T2 提示诊断 | 找出提示中缺失的上下文/约束/示例 |
| 验证可疑 API | T3 幻觉验证 | 让 Copilot 自我验证建议的准确性 |
| 迭代改进提示 | T4 提示对比 | 系统化对比不同版本提示的效果 |

---

## T1：根因分析

适用于：错误日志复杂、多层嵌套异常，需要快速定位真正原因。

```text
以上是错误日志。请：
1. 找出最根本的错误原因（不是最后一行 Exception，而是触发链的起点）
2. 列出由根因引起的次生错误（只列名，不分析）
3. 给出 2-3 个修复方向，按可能性从高到低排序
用中文简洁回答。
```

**已知局限**：日志超过 100 行时准确率下降，先用 `tail -50` 截取再传入。

---

## T2：提示诊断

适用于：Copilot 返回泛化或不满意的结果，需要找出提示的问题所在。

```text
我用以下提示让 Copilot 生成代码，但结果不满意：
"{你的原始提示}"

结果问题：{描述哪里不满意：太简单/框架错误/逻辑有误/重复已有代码等}

请按以下顺序诊断：
1. 上下文是否不足（缺少哪些文件或背景）
2. 任务描述是否有歧义
3. 约束是否不明确（框架/版本/限制条件）
4. 是否缺少示例输入/输出
并给出改进后的提示版本。
```

---

## T3：幻觉验证

适用于：Copilot 建议了某个 API、参数或功能，但不确定是否真实存在。

```text
你刚刚建议我使用 {具体API或参数}。
请确认：{库名} 的 {版本} 中是否真的有这个 {API/参数/功能}？
如果不存在，正确的替代方式是什么？
请提供一个可实际运行的代码示例。
```

---

## T4：提示对比迭代

适用于：系统化改进一个提示，每次只改一个变量观察效果。

```text
我对同一个任务测试了以下两个版本的提示：

版本 1：
{提示 v1}

版本 2：
{提示 v2，只修改了一处}

请分析：两个版本的差异点是什么？版本 2 的改进是否有效？
如果无效，建议下一步改变哪个维度（上下文/约束/示例/格式要求）？
```
