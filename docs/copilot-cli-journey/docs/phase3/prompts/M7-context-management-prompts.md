# M7 上下文管理 Prompt 模板库

本模板库用于 GitHub Copilot CLI 多文件任务的上下文建立、范围收敛、计划拆解和审查。建议按任务复杂度选择模板，并在长会话中持续更新上下文摘要。

## 快速选择表

| 场景 | 推荐模板 | 目标 |
| --- | --- | --- |
| 刚开始理解一个功能 | T1 上下文地图 | 建立关键文件、职责和关系视图 |
| 已知道目标但范围不清 | T2 修改范围收敛 | 明确必须修改、可能修改和不应修改 |
| 需要跨多个文件实施 | T3 多文件任务计划 | 拆解 3-5 个可验证步骤 |
| 完成修改后自查 | T4 Diff 审查 | 检查目标一致性和遗漏项 |
| 会话变长或准备交接 | T5 长会话上下文摘要 | 保留已完成工作、决策和下一步 |

## T1：上下文地图

用于在不修改代码的前提下，快速梳理与某个功能相关的文件和关系。

```text
请分析与 [功能名] 相关的文件，范围限定在 [目录路径]。

请输出：
1. 关键文件列表
2. 每个文件的主要职责
3. 文件之间的关系
4. 可能需要修改的位置

限制：不要修改代码，只做分析和说明。
```

## T2：修改范围收敛

用于把模糊需求转成清晰边界，避免不相关改动。

```text
请基于当前任务目标，帮我收敛修改范围。

请按以下结构输出：
1. 必须修改：完成任务不可缺少的文件或内容
2. 可能修改：根据实现方案可能需要调整的文件或内容
3. 不应修改：与任务无关、应避免改动的文件或内容

请说明每项判断理由，并优先保持改动最小化。
```

## T3：多文件任务计划

用于在实施前拆解跨文件任务，确保每一步都有验证方式。

```text
请为当前多文件任务制定实施计划，拆成 3-5 个步骤。

每一步必须包含：
1. 查看文件：需要先阅读或确认的文件
2. 修改文件：计划修改的文件
3. 验证方式：如何确认该步骤正确完成

请按依赖顺序排列步骤，并避免引入不相关改动。
```

## T4：Diff 审查

用于修改完成后审查 diff，确认任务目标和文档导航完整。

```text
请审查当前 diff，并重点检查：
1. 是否满足任务目标
2. 是否包含不相关改动
3. 文档链接是否正确
4. 导航或示例是否有遗漏

请按“问题 / 影响 / 建议修复”输出。如无问题，请说明已检查的重点。
```

## T5：长会话上下文摘要

用于长会话、交接或准备继续开发时压缩上下文。

```text
请总结当前长会话上下文，包含：
1. 已完成：已经做完的工作
2. 当前目标：正在解决的问题或下一阶段目标
3. 重要文件：后续需要关注的文件路径
4. 决策：已经确定的方案、约束或取舍
5. 下一步：建议继续执行的具体动作
6. 误区：需要避免的错误方向或不应重复的尝试

请保持简洁，确保新的会话可以直接接续工作。
```

## 使用建议

推荐顺序：T1 → T2 → T3 → T4 → T5。

1. 先用 T1 建立上下文地图，避免遗漏关键文件。
2. 再用 T2 收敛修改范围，减少无关改动。
3. 用 T3 拆解实施步骤，并在完成后用 T4 审查 diff。
4. 当会话变长或需要交接时，用 T5 生成上下文摘要。
