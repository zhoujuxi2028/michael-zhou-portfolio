### 2. 实战场景验证

**场景 1 — 复杂错误信息根因分析**

- 将 500 行 pytest Traceback 传入 Copilot，要求区分根因、次生错误、并给出修复优先级
- 关键发现：需在提示中明确"找出根本原因，不是最后一行 Exception"；日志过长时只传最后 50 行并使用 `--tb=short`
- 效果：将人工追踪多层嵌套异常的时间从约 20 分钟压缩到约 30 秒初步定位

**场景 2 — 迭代优化低质量提示**

- 以"生成用户注册函数"为例，从一句话提示（v1）逐步演进到含参数说明、约束和输入/输出示例（v3）
- 关键发现：每次只修改一个变量（上下文/约束/示例），才能准确判断哪项改进带来了质量提升
- 效果：系统化的迭代方法比反复猜测效率提升 3 倍以上，v3 提示质量评级从 ⭐ 提升至 ⭐⭐⭐⭐

**场景 3 — 处理 Copilot 幻觉输出**

- 验证了"自我验证"（让 Copilot 确认 API 是否存在）和"要求来源"（要求提供可运行示例）两种识别方式
- 关键发现：高可信场景（通用编程模式、主流库核心 API）可直接使用；低可信场景（具体版本号、复杂配置参数）需对照官方文档验证
- 效果：建立可信度分层规则后，日常使用中的验证工作量减少约 40%

## 核心学习成果

完成 M9 后，能在 Copilot CLI 中稳定完成以下工作：

1. **快速定位提示问题**：按四步诊断流程（上下文→任务→约束→示例）系统排查，而非凭感觉反复尝试。
2. **系统化迭代提示**：每次只改一个变量，通过对比观察效果变化，找到最有效的改进方向。
3. **识别并纠正幻觉**：用自我验证和要求来源两种方式检验 Copilot 的建议，对低可信内容及时查阅官方文档。
4. **建立个人失败案例库**：记录 Copilot 给出错误建议的场景，总结规律，持续改进提示习惯。
5. **用 AI 调试 AI**：把错误的 Copilot 建议直接反馈给 Copilot，形成"分析→纠正→改进"的闭环。
