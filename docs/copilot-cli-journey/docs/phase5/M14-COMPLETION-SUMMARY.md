### 2. 实战场景验证

**场景 1 — 编写团队 Copilot 使用规范**

- 提供团队背景（技术栈、框架、CI/CD、代码规范），用 Copilot 生成含五大章节的规范文档
- 关键发现：规范必须说明"为什么"而非只写"必须"，否则执行率极低；每条规范要配 good/bad 对比示例
- 效果：30 分钟内生成覆盖安全红线、质量检查、标准 Prompt 的完整规范草稿，比人工起草节省约 80%

**场景 2 — 建立可复用 Prompt 模板库**

- 设计 `.copilot-prompts/` 目录结构（testing/docs/git/review 四大分类），制定参数化模板格式
- 关键发现：模板用 `{PLACEHOLDER}` 标注可变部分；需要包含"已知局限"字段，避免在不适用场景误用；模板也需要版本控制
- 效果：标准化模板格式后，团队成员可直接复用，无需从零写 Prompt；通过 shell 别名进一步降低使用门槛

**场景 3 — Copilot Onboarding 流程设计**

- 提供新成员背景（经验、工具链、学习目标），生成 5 天实践导向的 Onboarding 计划
- 关键发现：每天任务需有明确验收标准（如"生成的测试能直接通过 pytest，覆盖率 ≥ 80%"）；第 5 天综合小项目作为能力验收
- 效果：结构化 Onboarding 使新成员达到独立使用水平的时间从 3-4 周缩短到约 1 周

## 核心学习成果

完成 M14 后，能在团队工作中稳定完成以下工作：

1. **快速起草使用规范**：用 Copilot 生成规范草稿，聚焦人工审核安全红线和质量要求，而非从零撰写。
2. **参数化 Prompt 库设计**：建立按场景分类、含示例和版本的可复用模板库，降低团队使用门槛。
3. **量化 Onboarding 目标**：把"会用 Copilot"拆解为每天可验证的任务，让新成员进度可追踪。
4. **识别推广阻力**：规范太严格或好处不明是推广失败的主因；试点→数据→推广的路径比自上而下强制执行更有效。
5. **分层建设标准**：个人 Prompt 库 → 团队规范 → CI 集成，三步递进建设，避免一步到位失败。
