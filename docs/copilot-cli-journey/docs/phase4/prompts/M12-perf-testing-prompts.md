# M12 性能/稳定性测试集成 Prompt 模板库

本模板库用于生成 k6 性能测试脚本、分析测试结果，以及设计稳定性测试方案。

## 快速选择表

| 场景 | 推荐模板 | 目标 |
|------|---------|------|
| 生成 k6 负载测试脚本 | T1 k6 负载测试 | 含 stages/thresholds/随机数据 |
| 分析 k6 测试结果 | T2 结果分析 | 判断是否达标并给出优化建议 |
| 生成稳定性测试脚本 | T3 Soak Test | 低并发长时间含告警条件 |

---

## T1：k6 负载测试脚本生成

```text
请生成一个 k6 负载测试脚本，测试以下 API：

{HTTP 方法} {URL}
Headers: {认证头}
Body: {请求体 JSON}
预期响应: {状态码}, {响应结构}

测试场景：
- 爬坡：{时长}内增加到 {并发数} 用户
- 稳定：持续 {时长}
- 降坡：{时长}内降到 0

性能目标（threshold）：
- http_req_duration P95 < {毫秒}ms
- http_req_failed < {百分比}%
- http_reqs > {每秒请求数} req/s

要求：
- {认证 Token} 从环境变量 __ENV.{变量名} 读取
- 每次请求使用随机生成的测试数据（避免缓存影响）
- 记录失败请求的详情
- 添加注释说明每部分的作用
```

---

## T2：k6 测试结果分析

```text
以上是 k6 性能测试的关键指标（P95/P99 响应时间、RPS、错误率）。请：
1. 判断是否达到性能目标（P95 < {毫秒}ms，错误率 < {百分比}%）
2. 如果未达标，找出瓶颈（响应时间分布异常/错误类型集中）
3. 给出 3 个具体的优化建议，按最可能有效到最复杂排序
用中文简洁回答。
```

**使用方式**：
```bash
k6 run --out json=/tmp/k6.json script.js
cat /tmp/k6.json | jq '.metrics | {p95:.http_req_duration.values["p(95)"], errors:.http_req_failed.values.rate, rps:.http_reqs.values.rate}' | gh copilot suggest "$(cat 上面的模板)"
```

## T3：Soak Test 稳定性测试脚本

```text
请生成一个 k6 稳定性测试脚本（Soak Test），要求：

测试场景：{时长}，{并发数} 个稳定并发用户
API：{端点描述}

监控项：
- 每隔 {间隔} 检测一次 P95 响应时间（检测性能退化趋势）
- 记录错误率变化

告警条件：
- P95 > {毫秒}ms 时打印警告日志
- 错误率 > {百分比}% 时中止测试

在注释中说明：为什么 Soak Test 使用低并发数而非压测并发数
```
