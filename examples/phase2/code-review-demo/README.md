## 💡 关键改进技巧

### 技巧 1: 从 N+1 到批量查询

```python
# ❌ 错误的做法
for user_id in user_ids:
    user = db.query(User).filter(User.id == user_id).first()  # N 次查询

# ✅ 正确的做法
users = db.query(User).filter(User.id.in_(user_ids)).all()  # 1 次查询
```

**改进效果**: 性能提升 **100-10000 倍**（取决于数据量）

### 技巧 2: 从字符串拼接到参数化查询

```python
# ❌ 危险的做法（SQL 注入）
query = f"SELECT * FROM users WHERE username = '{username}'"

# ✅ 安全的做法（参数化）
query = "SELECT * FROM users WHERE username = ?"
cursor.execute(query, (username,))
```

**改进效果**: 完全防止 SQL 注入攻击

### 技巧 3: 从 MD5 到 bcrypt

```python
# ❌ 不安全（已被破解）
hash = hashlib.md5(password.encode()).hexdigest()

# ✅ 安全（自动加盐、自适应）
hash = bcrypt.hashpw(password.encode(), bcrypt.gensalt(rounds=12))
```

**改进效果**: 密码安全性大幅提升，防止暴力破解

### 技巧 4: 从混乱到分层架构

```
重构前 (单一类混乱职责):
```
UserService
├── db.connect()
├── SQL 查询
├── 业务逻辑
├── 数据转换
└── UI 展示
```

重构后 (清晰的分层):
```
Repository (数据访问)
    ↓
Service (业务逻辑)
    ↓
DTO (数据转换)
    ↓
Controller (UI 展示)
```

**改进效果**: 代码易测试、易维护、易扩展

## 📝 快速参考

### 常用的 5 个改进模式

| 模式 | 用途 | 效果 |
|------|------|------|
| **N+1 → IN 子句** | 批量查询 | 100 倍性能提升 |
| **字符串拼接 → 参数化** | 安全查询 | 防止 SQL 注入 |
| **MD5 → bcrypt** | 密码安全 | 防止暴力破解 |
| **单方法 → 分层** | 可维护性 | 易于测试和扩展 |
| **无注释 → 完整文档** | 代码可读性 | 新手快速理解 |

- [ ] 错误处理是否完整？
- [ ] 代码注释和文档是否充分？

## 📞 常见问题

### Q: 我的代码也有这些问题，怎么办？

**A**: 不用担心！这很正常。按照本项目的改进步骤逐步修复：
